## Android 宿主

在宿主范围复用 `AndroidPermissionPlatform`。每个 `ComponentActivity` 创建时在主线程 `bind(activity)`，销毁时在主线程 `unbind(activity)`，同一 Activity 不得重复绑定。临时顶层 Activity 销毁后会恢复前一个绑定宿主；未绑定时查询/申请会等待宿主，调用协程应绑定页面生命周期。公开 suspend 入口内部切 Main；直接共享使用 `AndroidPermissionRequestHistory` 时，宿主也须在主线程读写同一实例。

按实际功能在 Manifest 声明 `android.permission.CAMERA`、`android.permission.RECORD_AUDIO`、`android.permission.ACCESS_COARSE_LOCATION`、`android.permission.ACCESS_FINE_LOCATION`。精确定位申请同时包含粗略定位。

`getStatus` 只读取状态；`request` 由用户操作触发；`resumeAfterSettings` 在 Android 的 `DENIED` 状态下可能再次申请，以兼容系统“每次询问”。不要把无 rationale 当作永久拒绝。解绑所属宿主会使挂起调用抛出异常；协程取消不能关闭系统弹窗，下次申请需等待真实回调或解绑。

已有权限历史保存在 SharedPreferences 时，用自有 namespace 构造：

```kotlin
val permissions = AndroidPermissionPlatform(historyPreferencesName = "legacy_permission_history")
```

保持旧 namespace 和权限枚举名（例如 `CAMERA`）即可，无需复制历史。默认 namespace 是 `gycrosskit_permission_history`；已授权事实始终以系统为准。

### 媒体权限执行器（自 0.1.2 提供）

```kotlin
val instanceHistory = AndroidPermissionRequestHistory()
val persistentHistory = AndroidPermissionRequestHistory(preferencesName = "legacy_permission_history")
val status = activity.requestRuntimePermission(android.Manifest.permission.CAMERA, instanceHistory)
```

默认 `AndroidPermissionRequestHistory` 只记录当前对象；picker 沿用实例范围，API 28 及以下保存相册的
WRITE_EXTERNAL_STORAGE 沿用宿主持有的进程范围对象。不要把这两种历史无条件改成持久化全局历史。
指定 namespace 时保持原 key；直接执行器以完整系统权限字符串为 key，`AndroidPermissionPlatform`
使用 AppPermission 枚举名，两者不能混用 key 来假装历史已经迁移。

`GRANTED` 直接执行，`REQUESTED_WITHOUT_RATIONALE` 不再次弹窗，首次/可解释拒绝会注册本次
RequestPermission launcher。false 回调只返回 DENIED；下一次调用才推断是否被系统阻止重申。
取消在主线程注销所属 launcher，系统授权框仍只能由用户结束，迟到回调不会恢复旧协程或进入新请求。
结果到媒体枚举/页面提示的映射由宿主完成。独立消费样例见 verification-consumer 的 AndroidProbe。
开发分支中，Launcher 注册或启动异常向调用方传播，不伪装成用户拒绝；仅启动受理后记录历史。失败不会让下一次调用误判为系统阻止重申。

## iOS

`IosPermissionPlatform()` 可在后台构造，公开 suspend 入口内部切换主线程，无需 UIViewController 绑定。取消可来自任意线程，定位等待归属的清理仍排到 Main，并按 continuation 身份判断，避免迟清理影响后继请求；不能关闭已展示的系统权限弹窗。按功能填写 Info.plist 的 `NSCameraUsageDescription`、`NSMicrophoneUsageDescription`、`NSLocationWhenInUseUsageDescription`。声明文案由宿主提供，缺少声明可能被系统终止。定位精度状态使用 iOS 14 API，因此宿主最低部署版本需设为 iOS 14 或更高。

## HarmonyOS 原生与 Kuikly

安装根 README 的 OHPM 包，在 UIAbility 内使用：

```typescript
import { GycPermissionService, GycPermission, GycPermissionStatus } from '@gycrosskit/permission-native';
const permissions = new GycPermissionService();
const before = permissions.getStatus('CAMERA');
const status = await permissions.request(context, 'CAMERA');
const restored = permissions.resumeAfterSettings('CAMERA');
```

`context` 是当前 `UIAbilityContext`。在 `module.json5` 中按需声明 `ohos.permission.CAMERA`、`ohos.permission.MICROPHONE`、`ohos.permission.APPROXIMATELY_LOCATION`、`ohos.permission.LOCATION`；精确定位与粗略定位一起声明/申请。

Kuikly Kotlin Pager 注册 `PermissionModule.NAME to PermissionModule()`（包 `io.github.gycrosskit.permission.kuikly`）；ArkTS render 的 Module 表注册 `GycPermissionModule.MODULE_NAME` 对应 `GycPermissionModule`。每页持有自己的 Kotlin Module，页面结束时 `dispose()` 取消挂起调用并移除回调；不要在 dispose 后复用。

调用和 dispose 均在页面 Kuikly 协程上下文执行；沿用 120 秒权限等待和 request Mutex。
超时/取消的 finally 移除 callback，dispose 只结束组件拥有的等待；不接管页面 ViewModel，也不声称可以撤回系统授权框。
