# permission 功能与平台差异

> 当前配套源码候选：Maven（core/Kuikly）、iOS Pod 与 OHPM 统一 `1.0.0`，Kuikly 基线 2.29.1。尚未发布；本地显式消费配套源码/HAR，旧 Release 与验收记录不能证明新版本可远程消费或已通过真机。

本地未发布接入候选：Kuikly Kotlin 为 `2.29.1-2.0.21-ohos`，原生 Pod 与 HAR Render 为 `2.29.1`。三端调用现有 PermissionModule，状态与取消合同共用；Android Activity 绑定/历史 namespace 由宿主提供。设置返回策略和已显示的系统权限弹窗屏障属于明确平台差异，不能为消除 busy 而抢占仍显示的系统弹窗。源码接线、本地编译、真机与远程消费分别验收；下方带日期/版本的结果保留历史范围。

已发布基线 Maven `0.1.9` 提供 `permission-kuikly` Android、iosArm64、iosX64、iosSimulatorArm64 targets、原生 receiver 和每 Renderer handler。iOS 可选 Pod `GycPermissionKuikly/Kuikly` `0.1.9` 使用真实 `OpenKuiklyIOSRender 2.28.0`；Kotlin handler 由宿主已有 Shared framework 导出。发布与远程消费状态以[对应 Release](https://github.com/gycrosskit/permission/releases/tag/0.1.9)为准。历史基线 Maven `0.1.8` 的 `-kuikly` 仅含 OHOS 变体；原 HAR 沿用。宿主需注册并维护已有原生能力 owner，示例见[接入指南](接入指南.md#androidios-kuikly-native-module)。


本次版本：Maven `0.1.8`。等待原生权限请求终态再释放 owner，取消的调用方不再导致下一次请求抢占。HAR 0.1.6 沿用。发布后以该不可变标签与渠道收据确认，以下既有发布记录保留历史范围。

历史发布记录（不含本次修复）：Maven 0.1.7；HAR 0.1.6沿用原字节。源码基线：`2789f8184303afb76a7f6a424ce862f1ebf2a8c2`，叠加本次修复；最终源码由不可变Git标签`0.1.7`定位。构建、checksum及各渠道实际验收结果见[版本发布记录](https://github.com/gycrosskit/permission/releases/tag/0.1.7)，源码/替身测试范围见本页验证表；不声明真实设备业务验收通过。

## 产物与职责

| 模块/产品 | 实际职责 |
|---|---|
| `permission-core` | PermissionPlatform.getStatus/request/resumeAfterSettings、PermissionRegistry/PermissionHandler、AppPermission、PermissionStatus；Android/iOS实现。 |
| `permission-kuikly` | PermissionModule 调用侧、AndroidPermissionModule / IosPermissionModuleHandler 接收端；名称 GycPermissionModule，OHOS 原协议保持。 |
| `@gycrosskit/permission-native` | API22 HAR，GycPermissionService和GycPermissionModule；直接ArkTS可使用service。 |

构建边界：[core构建](../permission-core/build.gradle.kts)、[Kuikly构建](../permission-kuikly/build.gradle.kts)、[模块清单](../settings.gradle.kts)、[OHOS SDK配置](../ohos/build-profile.json5)。

本库提供原生 core 能力与 Kuikly 接线，不提供独立页面 UI。Kuikly Android/iOS 使用原生 receiver，宿主装配能力 owner 与注册入口。库不自动注册 Renderer，也不提供品牌验收。

## 三端功能矩阵

三端分别列出原生能力与 Kuikly 接线；“OHOS Module已实现”表示已有 Kotlin/ArkTS 调用链。宿主负责注入原生 owner 和注册 Module；矩阵说明源码接入边界，实际行为验证见下方验证范围。

| 功能/API组 | Android（原生 / Kuikly） | iOS（原生 / Kuikly） | OHOS（原生 / Kuikly） |
| --- | --- | --- | --- |
| getStatus：三种内置能力 / 六种状态 | 原生：原生实现，宿主注入；Kuikly：Native Module源码，须注册 | 原生：原生实现，宿主注入；Kuikly：Native Module源码，须注册 | OHOS Module已实现 |
| request / 系统弹窗串行 | 原生：原生实现，宿主注入；Kuikly：Native Module源码，须注册 | 原生：原生实现，宿主注入；Kuikly：Native Module源码，须注册 | OHOS Module已实现 |
| resumeAfterSettings | 原生：原生实现，宿主注入策略；Kuikly：Native Module源码，须注册 | 原生：原生实现，宿主注入重读；Kuikly：Native Module源码，须注册 | Module策略，见差异 |
| 宿主能力 key 注册 / 三方法透传 | 原生 Registry；Kuikly 注入既有 owner | 原生 Registry；Kuikly handler 接收 PermissionPlatform | Service 注册 handler；Module 可注入 service |
| AndroidRuntimePermission扩展 | A扩展/宿主注入 | 不支持A扩展 | 不支持A扩展 |

## 公开 API 组

- `PermissionPlatform.getStatus(AppPermission)` / `request` / `resumeAfterSettings`；能力CAMERA/MICROPHONE/LOCATION_WHEN_IN_USE；String overload 与 `PermissionRegistry` / `PermissionHandler` 支持宿主能力 key，六状态及allowsUse由common声明。
- Android额外`bind` / `unbind`、`AndroidPermissionRequestHistory`与`AndroidRuntimePermission`执行器；Kuikly Module页面退出`dispose()`。

## API 合同与差异分类

| 分类 | 具体输入 / OS / SDK边界 | 调用方应如何处理 |
|---|---|---|
| 组件边界 | 内置CAMERA/MICROPHONE/LOCATION_WHEN_IN_USE；String key 需宿主按端注册；NOT_DETERMINED/GRANTED/LIMITED/DENIED/RESTRICTED/UNSUPPORTED。 | allowsUse仅GRANTED/LIMITED；无后台定位、整库相册或设置页跳转API。UNSUPPORTED 表示当前平台未注册能力，不引导设置恢复。A独立AndroidRuntimePermission执行器不是公共六状态的同名替代。 |
| 组件边界 | AndroidRuntimePermission 执行器已授权或系统策略受限时直接返回；其余状态在用户主动操作时申请一次，包括一次授权失效后的再次申请。 | false 回调在策略限制时返回 RESTRICTED，其余返回 DENIED；申请历史、无 rationale 与保留的 REQUESTED_WITHOUT_RATIONALE 均不能证明永久拒绝或要求跳转设置。 |
| 厂商限制 | 粗略位置A/O及iOS14+ reducedAccuracy返回LIMITED。 | LIMITED可继续使用，但不能承诺满足业务精度；权限不等于定位服务开启。 |
| 组件边界 | 设置恢复：A getStatus为DENIED时受控request；i重读；OHOS原生service只重读，KotlinModule为NOT_DETERMINED时request。 | 这是当前各入口的恢复策略差异；宿主应在明确返回设置时调用，不把它当全平台纯查询或自动弹窗。 |
| 组件边界 | A候选调用API23公开isPermissionRevokedByPolicy；本库minSdk24。 | 完整/粗略授权优先，否则policy限制映射RESTRICTED；企业管理员实机尚未验证。 |
| 厂商限制 | 取消不能关闭系统权限弹窗。 | Android/iOS串行屏障与O进程队列等待实际回执；页面销毁跳过未开始的请求，旧回执不交给新owner。 |
| 宿主职责 | A绑定/解绑当前ComponentActivity与历史namespace；iOS14+声明用途；OHOS目标/兼容API22声明实际权限。 | 维护页面生命周期、解释文案与设置页导航，组件不决定申请时机。 |
| 未验收 | 真实系统prompt、每次询问、设置往返、企业策略和品牌说明文案。 | mock与状态resolver测试不证明用户授权或市场合规验收。 |

## 验证范围

本轮宿主能力扩展：`verification-kuikly` 本地 JVM 实际执行 14 例，零失败/错误/跳过；新增路径把自定义 key 从生产 caller 透传到生产 handler 与 Registry，检查 query/request/resume、未注册 key、原生权限串不自动授权、旧 enum 调用及注册冲突。扩展挂起查询取消/120 秒超时的回归已确认修复前缺少 `cancelQueued` 而失败，修复后按同一 requestId 取消原生协程并执行监听清理 finally；不提前释放系统弹窗 owner 屏障。Node 转译生产 ArkTS 实际执行 5 例，零失败/跳过，覆盖 service/宿主 receiver 子类注入、三方法透传与原有全局取消屏障。SDK/传输为替身，不证明真实系统权限或三端 SDK 编译。Android helper 新增 policy→RESTRICTED 回归，本轮尚未执行 Android SDK 测试；重 SDK 编译、真机和远程消费由独立验证记录确认。


本次未发布修复调整 AndroidRuntimePermission 的再次申请合同；现有 `AndroidRuntimePermissionTest` 已更新初次拒绝与持久化历史下“授权→撤销→再次申请成功”的断言。SDK 28 Robolectric 只替代授权事实和回调，不证明 Android 11+ 一次权限真实失效行为；本次 Android SDK 测试尚未执行，系统弹窗、永久拒绝与设置往返仍待设备验收。

本轮 `1.0.0` Native Module 候选新增 [`PermissionModuleHandlerTest`](../verification-kuikly/src/test/kotlin/PermissionModuleHandlerTest.kt)：执行生产 handler，JSON/Kuikly transport 为验证替身，检查请求 ID 取消、共享 owner、销毁后的旧结果隔离及状态/非法输入。本轮独立 JVM 检查共 11 例通过，零失败/跳过；Android release 与 iOS Simulator Kotlin 编译通过。真实 OpenKuiklyIOSRender 2.28.0 的 Pod source 构建与 Simulator receiver 生命周期检查通过，覆盖 typed SDK 调用、重复失效、Main 排队调用、工厂创建竞态、Context 排队回调隔离与 SDK dealloc；handler 为受控闭包，未调用权限/相册/定位业务。源码门禁及复现命令见[开发与验证](开发与验证.md)。以上为本轮源码验证，不代替远程消费或真机业务验收；发布状态以对应 Release 为准。
