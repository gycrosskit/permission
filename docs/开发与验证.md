## 环境与检查

源码构建使用 JDK 17、Gradle wrapper、Android SDK（compileSdk 36）；iOS 需要 macOS/Xcode，HarmonyOS HAR 需要匹配 API 22 的 DevEco SDK、ohpm 与 hvigorw。先配置 `ANDROID_HOME` 和 HarmonyOS 工具链路径，命令从仓库根目录运行；以下是维护者检查命令，不是第三方安装步骤。

```sh
bash gradlew :permission-core:compileDebugKotlinAndroid :permission-core:testDebugUnitTest :permission-core:compileKotlinIosSimulatorArm64 :permission-core:compileKotlinOhosArm64 :permission-kuikly:compileKotlinOhosArm64
node --test ohos/permission-native/test/permission.test.cjs
bash gradlew -p verification-consumer compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosX64 linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64
```

HarmonyOS HAR 在 `ohos/` 内执行：

```sh
ohpm install --all
hvigorw --mode module -p module=PermissionNative@default -p product=default assembleHar --no-daemon
```

需要 SDK 的检查只在对应环境执行；不默认 `clean` 或全仓库构建。独立消费者使用 README 的远程 Maven 坐标，不使用 `mavenLocal` 或源码 `project/includeBuild` 替换。

## Maven 产物维护

Maven Android/iOS/OHOS（按本库实际 target）产物在 macOS 生成并放入版本化 Release 归档；JitPack 下载对应不可变标签的归档，校验 SHA-256 后安装。源码检查不能替代完整 KMP `.module` 与每个引用产物的检查；本地 Maven 验证不能替代默认远程消费。标签、归档与校验和不得覆盖，Maven 二进制不提交到源码仓库。

完整发布步骤与不可变产物约束见 [GY CrossKit 发布流程](https://github.com/gycrosskit/.github/blob/main/docs/发布流程.md)，历史版本见 [发行页](https://github.com/gycrosskit/permission/releases)。
